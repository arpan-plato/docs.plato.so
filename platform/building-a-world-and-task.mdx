Creating a world drops you into the **editor** — the single screen where you do all your building. It has three panels: the **assistant** on the left, the **task** in the middle, and the **benchmark** tools on the right.

## The workspace: running vs. stopped

A world is either **running** or **stopped**. While it's **running**, it's open for you to work in and make changes. When it's stopped, you see a **read-only snapshot** of your last saved state — you can look but not edit until you start it up again.

- **Stop workspace** (top right) pauses the world when you're done. Your work is saved, and there's no need to keep it open while you're away.
- Reopening a stopped world shows that last saved state; start it up again to make changes.

## The Agent panel (left) — your build assistant

The left panel is the **world-building assistant**. This is your main tool for setting up the environment: you tell it, in plain language, what apps and data the world should contain, and it does the work — creating files, seeding records, wiring up the simulators.

- As it works, you'll see its steps appear as a list (each marked **Completed** when done), and it reports back in plain language about what it did and what's left.
- Think of it as a capable teammate doing the setup for you. You describe the scenario — *"seed a Gmail inbox with a message from the CFO, and a Google Sheet with these three proposals"* — and it builds it.

<Note>
The assistant builds the **environment** for you. The **task instruction** and the **grading criteria**, though, are yours to write — that's the expert judgment only you can supply. Use the assistant to set the stage, not to decide what "correct" means.
</Note>

## The center panel — Task, Services, and Verification

The middle of the editor is where your task actually lives, in three sections.

### Task

The **instruction handed to the benchmark agent** — the assignment it will try to complete. Write it here; edits **save automatically** into the world.

Keep it to what a manager would actually send: short and natural. You don't need to spell out every step.

<Note>
**One task per world.** A world holds a single task — there's no way to add a second one. To build another task on the same environment, clone the world (see [Reusing seed data for a new task](#reusing-seed-data-for-a-new-task) below).
</Note>

### Services

The **simulators** — the apps your task runs on (Gmail, Google Sheets, an accounting tool, and so on). Each one is a fixed, locked version that's **set up fresh for every run**, so every test of your task starts from the exact same clean state.

You generally set these up through the assistant rather than by hand.

### Verification

**What each run is graded on**: a list of plain **criteria**, each a specific statement an agent **judge** marks pass or fail after the run. This is your grader.

- Add one criterion per thing you want checked — a value, an action, a clear yes/no.
- A **judge profile** decides how the criteria are evaluated; it's shown at the bottom of this section.

<Tip>
The Task, Services, and Verification you see together here are the complete definition of your task. If it's not in one of these three, it won't affect the run or the grade.
</Tip>

## Versions save themselves

At the top of the editor you'll see the task selector, a **Checkpoint** marker, and **All versions**. Every time you checkpoint your work, Plato saves a **version** automatically — you don't manage this by hand. It keeps a record of how the task evolved so you (and we) can see each change and the results it produced. Iterate freely; the history is kept for you.

## Reusing seed data for a new task

A world is deliberately **one task, one world** — you can't add a second task to it. But often you'll want another task built on the *same* environment: the same seeded inbox, workbook, and records. When you do:

<Steps>
  <Step title="Clone the world">
    Use the **clone** action (the copy icon) on the world's card in the dashboard. This gives you a fresh, editable copy with all the same simulators and seed data.
  </Step>
  <Step title="Change the task in the copy">
    In the clone, rewrite the **Task** instruction and adjust the **Verification** criteria for the new assignment. The environment carries over, so you only change what the task asks for.
  </Step>
</Steps>

This keeps each task cleanly in its own world — which is what we review — while letting you reuse the setup work you've already done.
