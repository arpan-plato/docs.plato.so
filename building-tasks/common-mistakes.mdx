---
title: "Common mistakes to avoid"
description: "The handful of things that most often make a task weak — and how to fix each."
---

Almost every task that gets sent back trips on one of these. Skim them before you build, and again before you submit.

## Telling the agent how to do the work

The most common one. The instruction spells out the method — which test to run, which figures matter, what the standard is. Now you're only testing whether the agent can follow steps.

**Fix:** move the "how" into the world. Put the policy in a document, the figures in the workbook, the context in an email. Keep the instruction to the real request a manager would send.

## The task is too easy

The AI passes on the first try, every time. A task nothing fails isn't measuring anything.

**Fix:** harden it in a loop — tighten the data, add real complications, remove the hand-holding — until a capable agent genuinely fails. A task that passes every run isn't finished; it's unproven.

## Letting the AI invent the ground truth

If you ask the building assistant to "make it hard and write the criteria," the *assistant* is now supplying the expertise — not you. The answer key might be wrong, and you won't know. A failure could just be the agent being right and the AI-generated key being wrong.

**Fix:** you provide the real data and you decide the right answers. Use the assistant to build the environment and review your work, never to author the judgment.

## Criteria that fail a competent professional

A criterion demands one specific answer, but the evidence genuinely supports more than one defensible conclusion. Good work fails because it disagreed with your single preferred answer.

**Fix:** either make the world unambiguous (so there really is one right answer), or write the criterion to accept any defensible conclusion and fail only the clearly-wrong ones. Ask yourself: *could a careful expert defensibly fail this check while doing good work?* If yes, fix it.

## The instruction and the checks don't match

The task asks for one thing ("send me your recommendation") but the criteria grade another ("the model was edited"). An agent that does exactly what it was asked still fails.

**Fix:** make sure everything a criterion checks for is something the task actually asked for.

## Placeholder or vague criteria

Checks like "the agent accomplished the task" or "the analysis is thorough" can't be graded reliably and will be sent back.

**Fix:** every criterion should state something specific and checkable — a value, an action, a clear yes/no.

## Over-long instructions

A 500-word instruction that lists every deliverable and names every figure. It reads like documentation, not like a real manager's ask — and it usually leaks the method.

**Fix:** if a colleague would already know to do something, don't write it down. The details belong in the world (a checklist tab in the workbook, the policy document), not in the assignment. Shorter is usually both more realistic *and* harder.

## Several tasks crammed into one world

Harder to review, and the versioning gets tangled.

**Fix:** one task per world.

---

If you've avoided all of these, you're in good shape. When in doubt, the north star is simple: **build the real work, hide the method in the world, and make sure a capable AI fails for a reason you'd recognize as a genuine mistake.**
